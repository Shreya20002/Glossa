# Security Policy

## Supported versions

Glossa is a young project. Only the **latest release** receives security fixes.

## Reporting a vulnerability

**Please do not open a public issue for security problems.** Public issues can
be read by attackers before a fix exists.

Instead, report it privately through GitHub:

1. Go to the repository's **Security** tab.
2. Click **Report a vulnerability**.
3. Describe the problem, how to reproduce it, and its impact.

Only the maintainers can see your report. We'll work on a fix with you in a
private advisory, and credit you when it's published (unless you'd rather stay
anonymous).

## What to expect

Glossa is maintained by volunteers, so timelines are best effort:

- **Acknowledgement** within 7 days.
- **Assessment** (is it a vulnerability, how severe) within 14 days.
- **Fix and disclosure** coordinated with you — usually within 90 days.

## What counts as a security issue here

Glossa's main promises are privacy and safety, so we especially want to hear
about anything that could:

- Make Glossa send data over the network.
- Save, leak, or expose audio or transcripts.
- Let a web page, file, or other process run code inside Glossa.
- Tamper with installers, models, or the release pipeline.

Bugs that are annoying but not exploitable (crashes, wrong counts) belong in a
normal bug report.
